# Lab 3: Manage context and split work

**Time:** 35 minutes · **Mode:** small groups

## Scenario

An agent has searched broadly, read generated files and long logs, and is now forgetting the acceptance criteria for a multi-file change.

## Exercise

1. Identify which context is authoritative, useful, duplicate, or noise.
2. Rewrite the request as three stages: discovery, plan/review, and implementation/verification.
3. Define a short checkpoint that preserves the goal, decisions, files, unresolved questions, and next action.
4. Choose one bounded implementation stage and specify only the source/tests it needs.
5. Compare the two prompts. Record what you removed and why.

## Individual challenge

Use an editor context indicator or available session UI if present; record what it reports, but do not infer a universal token limit. Model availability and context capacity vary by product surface and plan.

## Deliverable

The staged prompt outline, checkpoint note, evidence set, and a short rationale explaining how the split reduces noise without omitting required facts.
